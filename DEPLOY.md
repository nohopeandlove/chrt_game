# Развёртывание и дальнейшая работа

Инструкция для того, кто будет размещать игру «Я — специалист» на сайте
и продолжать разработку. Предварительных знаний о проекте не требуется.

## Что это за проект

Браузерная игра-новелла, полностью статичная: HTML, CSS и JavaScript.
Сервера, базы данных и сбора статистики нет. Прогресс игрока хранится
в его браузере (`localStorage`). Звука нет. Вся графика — SVG, который
рисуется кодом, поэтому растровых картинок в игре нет.

## Вариант 1. Просто выложить готовую игру

Подходит, если нужно только разместить игру, а код менять не нужно.

1. Возьмите папку `site/` из архива (или `dist/` после сборки, см. ниже).
2. Загрузите **всё её содержимое** в любую папку на сайте техникума,
   например `/trudoustroystvo/igra/`. Подойдёт любой хостинг, который
   умеет отдавать обычные файлы: Apache, nginx, IIS, конструктор сайтов
   с файловым менеджером.
3. Откройте в браузере адрес этой папки — должна появиться главная
   страница игры.

Пути внутри сборки относительные, поэтому папку можно положить на любую
глубину и переименовать как угодно.

**Встроить в страницу сайта** можно через `iframe`:

```html
<iframe src="/trudoustroystvo/igra/index.html"
        style="width:100%; aspect-ratio:16/9; border:0"
        title="Игра «Я — специалист»"
        allow="fullscreen"></iframe>
```

**Важно:**

- Открывать нужно через `http(s)://`, а не двойным кликом по
  `index.html` с диска — браузер не загрузит модули со схемы `file://`.
  Для проверки на своём компьютере используйте `npm run preview`
  (см. ниже) или любой локальный веб-сервер.
- Шрифт Rubik подгружается с `fonts.googleapis.com`. Если доступ к Google
  из сети техникума закрыт, игра всё равно работает — текст покажется
  системным шрифтом.
- Если игру обновили, а у студентов видна старая версия — это кэш
  браузера. Файлы со скриптами и стилями получают новые имена при каждой
  сборке, поэтому достаточно обновить `index.html`; в крайнем случае —
  Ctrl+F5.

### Бесплатная публикация на GitHub Pages

Код уже лежит в репозитории
[thisTORPEDA/ya-specialist2026](https://github.com/thisTORPEDA/ya-specialist2026).
Чтобы получить постоянную ссылку вида
`https://thistorpeda.github.io/ya-specialist2026/`:

1. Соберите проект (`npm run build`).
2. Опубликуйте папку `dist/` в ветку `gh-pages`, например:
   ```bash
   npx gh-pages -d dist
   ```
3. В настройках репозитория на GitHub: **Settings → Pages → Branch:
   `gh-pages`**.

## Вариант 2. Работать с исходным кодом

### Что нужно установить

- **Node.js 24 или новее** — https://nodejs.org (версия LTS).
  Проверка: `node --version`.
- **Git** — для работы с репозиторием (необязательно, если взяли код из
  архива).
- Любой редактор кода: VS Code, WebStorm и т. п.

### Первый запуск

```bash
npm install        # один раз: скачает Vite и TypeScript (~25 МБ)
npm run dev        # игра на http://127.0.0.1:5173, обновляется при правках
```

### Команды

| Команда | Что делает |
|---|---|
| `npm run dev` | Запускает игру для разработки с автообновлением |
| `npm run check` | Проверяет контент и типы. Запускать перед каждой сборкой |
| `npm run content` | Проверяет только контент (работает без `npm install`) |
| `npm run build` | Собирает игру в папку `dist/` для выкладки |
| `npm run preview` | Показывает собранную версию из `dist/` |

### Типовой цикл обновления

```bash
npm run check      # «Всё в порядке» — можно собирать
npm run build
# содержимое dist/ загрузить на сайт поверх старой версии
```

## Как менять тексты без программиста

Весь текст игры лежит в папке `content/` в формате JSON. Код для этого
трогать не нужно.

| Что поменять | Где |
|---|---|
| Реплики, выборы, главы | `content/scenes/00-prologue.json` … `07-first-day.json` |
| Вакансии и секретные слова | `content/vacancies.json` |
| Вопросы тестовых заданий | `content/tests.json` |
| Специальности и их навыки | `content/specialties.json` |
| Имена и цвета персонажей | `content/characters.json` |
| Достижения | `content/achievements.json` |

Подстановки в тексте:

- `{playerName}` — имя, которое ввёл игрок;
- `{g:мужская|женская}` — форма слова по выбранному персонажу,
  например `{g:закончил|закончила}`.

**После любой правки** запустите `npm run content`. Проверка поймает
сломанный JSON, ссылку на несуществующую сцену или персонажа, неверный
номер правильного ответа и — важно для вакансий — секретное слово,
которого нет в тексте описания. Полное описание форматов —
`content/schema/README.md`.

## Устройство кода

```
src/
  main.ts              точка входа: меню → игра → «Пройти заново»
  engine.ts            проигрывает сцены узел за узлом
  ui.ts                реплики, выборы, заставки, меню
  state.ts             состояние игрока и сохранение в браузере
  text.ts              подстановки {playerName}, {g:…|…}
  content.ts           загрузка JSON из content/
  screens/             интерактивные экраны: резюме, вакансии, тест,
                       отдел кадров, финал
  render/portrait.ts   портреты персонажей (SVG из параметров)
  render/backgrounds.ts  семь анимированных локаций
  styles.css           весь внешний вид, стиль «комикс»
tools/validate.mjs     проверка контента, без зависимостей
```

Новый тип экрана добавляется так: модуль в `src/screens/`, ветка в
`engine.ts` (метод `playNode`), узел с этим `screen` в нужной сцене.
Неизвестный тип узла движок не пропускает молча, а останавливается
с ошибкой — так недоделки видны сразу.

## Решения, которые уже приняты

- Статичная сборка, без сервера и без сбора статистики.
- Без звука.
- Интерфейс в стиле «комикс»; шрифт Rubik.
- Персонажи — плоский вектор (манера `flat` в `src/render/portrait.ts`).
  Другие манеры (`ink`, `chibi`, `minimal`) уже есть в коде и включаются
  одной константой `DEFAULT_LOOK`. Проба объёмных персонажей лежит
  в `design/mocks/characters-3d.html` — в игру не встроена.
- Все правки к исходному сценарию перечислены в `docs/changes.md`
  с объяснением, где и почему.

## Что осталось сделать

1. **Список специальностей ЧРТ.** Сейчас в `content/specialties.json`
   четыре условные группы: программирование, информационная
   безопасность, сети и администрирование, реклама. Нужно заменить их
   реальными выпускными специальностями и при необходимости привязать
   к ним вакансии (`specialties` у вакансии) и наборы тестов
   (`specialty` у набора в `tests.json`). Проверка подскажет, если у
   какой-то специальности не окажется вакансии или теста.
2. **Имя HR-менеджера.** В сценарии его не было, стоит рабочее
   «Алина Дмитриевна» — меняется в `content/characters.json` и
   в репликах `content/scenes/05-interview.json`.
3. **Пилот с группой** и правки по итогам.

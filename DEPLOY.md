# Развёртывание: общий сервер игры и отдельный кабинет преподавателя

## Что нужно

Один сервер для всей группы, Docker Engine + Docker Compose v2, постоянный диск.
Практичный стартовый ориентир для небольшого пилота: VPS с 1–2 vCPU, 2 ГБ RAM и
10 ГБ диска. Это рекомендация, а не результат нагрузочного тестирования.
Для публичного размещения нужен домен и HTTPS. Серверная часть использует Node.js 24
и SQLite; игровой интерфейс собирается Vite. Встроенная авторизация преподавателя
настоящая серверная: пароль хранится как scrypt-хеш, сессия — в HttpOnly cookie.

## Локальная проверка

Из корня проекта: `docker compose up --build -d`.
Игра открывается на http://localhost:8080, преподаватель — на /teacher/.
Получите код настройки в терминале администратора:

```bash
docker compose exec game node server/manage.mjs setup-code
```

Код введите на странице `/teacher/` вместе с новым логином и паролем от 12 символов.
Код одноразовый и хранится только в каталоге базы; он не публикуется в приложении,
репозитории или обычных логах. После настройки войти можно только с вашим паролем.

## VPS с доменом: подготовленная конфигурация

1. Создайте VPS с Docker и постоянным диском у выбранного провайдера.
2. Направьте DNS-запись A вашего домена на IP сервера. Если есть AAAA, она тоже
   должна указывать на этот сервер. Откройте входящие TCP 80 и 443 для HTTPS.
3. Склонируйте репозиторий на сервер. В его папке создайте `.env`:

```dotenv
GAME_DOMAIN=game.example.org
```

Замените пример своим доменом, без `https://` и пути. `.env` не попадает в Git/образ.

4. Запустите:

```bash
docker compose -f compose.yaml -f compose.host.yaml up --build -d
```

Caddy принимает HTTPS и автоматически получает сертификат для указанного домена.
Приложение доступно через `game:3000` внутри Docker; внешний порт 8080 остаётся
привязан только к localhost сервера. Cookie преподавателя в этом режиме имеет Secure.
Провайдер должен разрешать получение TLS-сертификатов. Если DNS/порты/сертификат
не настроены, публичная готовность не подтверждена: смотрите логи proxy.

5. В консоли сервера выполните команду `setup-code` выше и настройте преподавателя
   на `https://ваш-домен/teacher/`.
6. Студентам отправьте только `https://ваш-домен/`. Пароль и код преподавателя
   студентам не передаются. Каждый начинает собственное прохождение с учебным
   кодом/псевдонимом и группой; результаты появляются автоматически.

Конфигурация HTTPS подготовлена для размещения, но выдача сертификата и работа
на реальном домене должны быть проверены после выбора хостинга. Публичный адрес
в рамках локальной доработки не создаётся.

## Хостинг с собственным reverse proxy

Можно запускать Dockerfile как один сервис, публикующий внутренний порт 3000.
Установите `COOKIE_SECURE=true`, подключите постоянный диск к `/data` и убедитесь,
что пользователь контейнера (UID 1000) может писать туда. Proxy должен сохранять
исходный заголовок Host и обслуживать весь домен: `/`, `/api/`, `/teacher/`.
Настройте HTTPS на стороне провайдера. Проверка здоровья: `GET /api/health`.
Не размещайте только `dist/`: для базы и входа требуется работающий сервер.

## Обновление и сохранность данных

На том же сервере, из той же папки и с тем же именем Compose-проекта:

```bash
git pull
docker compose -f compose.yaml -f compose.host.yaml up --build -d
```

Для локального режима опустите `-f ...` и используйте `docker compose up --build -d`.
Образы можно пересобирать; база хранится в Docker volume. Не используйте `down -v`
и не удаляйте volume `game-data`, если хотите сохранить журнал.

Пример резервной копии с краткой остановкой записи:

```bash
docker compose stop game
docker compose cp game:/data ./game-data-backup
docker compose start game
```

Если каталог копии уже существует, выберите новый путь. Храните копии отдельно
от сервера и проверяйте восстановление на тестовом экземпляре. На хостинге также
настройте резервное копирование постоянного диска.

## Если забыт пароль преподавателя

Только администратор, имеющий консоль сервера, может сбросить вход:

```bash
docker compose exec game node server/manage.mjs reset-login --confirm
docker compose exec game node server/manage.mjs setup-code
```

Результаты студентов сохраняются; старые сессии преподавателя аннулируются.
Затем создайте новый вход на `/teacher/`. При обычном обновлении это не требуется.

## Границы реализации

Одна учётная запись преподавателя на экземпляр сервера; она видит все группы.
Есть фильтры по группе и учебному коду, просмотр по 50 прохождений и CSV всех
результатов выбранного фильтра. Разграничение нескольких преподавателей по группам
пока не реализовано. Учебный код вводится самим студентом, а результаты вычисляются
клиентом; система не подтверждает личность и не является защищённой аттестацией.
Для реального занятия учреждение определяет допустимые данные и сроки их хранения.

# Размещение игры на хостинге приложений

Эта инструкция относится к сервису, который сам собирает и запускает приложение
из GitHub. Покупать и настраивать VPS для этого не требуется.

## Требования к тарифу

- Запуск Dockerfile из репозитория или Node.js 24.
- Постоянный диск, который не очищается при обновлении приложения.
- HTTPS и публичный адрес, предоставляемые хостингом.
- Приватная консоль запущенного приложения для первоначальной настройки преподавателя.
- Один экземпляр приложения: SQLite хранится на одном диске. Несколько реплик
  без общей базы для текущей версии не поддерживаются.

Бесплатный тариф без постоянного диска не подходит для хранения журнала преподавателя.
Цены, доступность оплаты и условия диска нужно проверить у выбранного провайдера.

## Настройки приложения

Подключить репозиторий `nohopeandlove/chrt_game`, ветку `main`.

**Рекомендуемый вариант — Docker:**

- Контекст сборки: корень репозитория.
- Dockerfile: `Dockerfile`.
- Команда запуска уже задана в образе: `node server/app.mjs`.
- Внутренний порт: `3000`. Если провайдер передаёт переменную `PORT`, приложение её использует.
- Интерфейс прослушивания: `0.0.0.0` (значение по умолчанию).
- Проверка здоровья: `/api/health`.
- Постоянный диск: подключить к `/data`, предоставить пользователю контейнера
  UID 1000 право записи. Если хостинг требует другой путь, использовать его
  и указать тот же путь в `DATA_DIR`.
- Переменные: `NODE_ENV=production`, `DATA_DIR=/data`, `COOKIE_SECURE=true`.
- Число экземпляров: `1`.

Docker Compose и Caddy на таком хостинге не запускаются: HTTPS обслуживает провайдер.
Не выбирать тип «статический сайт» и не публиковать только каталог `dist/`.

Если хостинг поддерживает только Node.js: выбрать версию 24, команду сборки
`npm ci --include=dev && npm run check && npm run build`, запуск `npm start`.
Постоянный каталог и переменные настроить так же.

## После первого размещения

1. Открыть выданный HTTPS-адрес. По `/api/health` должен возвращаться `{"ok":true}`.
2. В приватной консоли приложения выполнить:

   ```sh
   node server/manage.mjs setup-code
   ```

3. Открыть `https://адрес-игры/teacher/`, ввести код, задать логин и пароль
   от 12 символов. Код и пароль не отправлять в чат и не сохранять в GitHub.
4. Открыть игру в другом браузере, ввести учебный код и группу, выполнить задание.
   Проверить появление результатов в кабинете преподавателя.
5. Перезапустить или повторно развернуть приложение. Проверить, что вход
   преподавателя и результаты сохранились. Если нет — постоянный диск настроен неверно.
6. Настроить резервное копирование постоянного диска средствами провайдера.

Студентам передать адрес игры; преподавателю — адрес с `/teacher/`.
При включённом автоматическом обновлении новые коммиты `main` вызывают пересборку
на хостинге. Архивы скачивать не нужно. Подключённый диск должен сохраняться при обновлении.

Сам файл инструкции не создаёт аккаунт, платный сервис или публичную ссылку.
Публикация выполняется после подключения аккаунта хостинга.

## Amvera: первоначальный вход без консоли

Если провайдер не предоставляет консоль контейнера, в разделе «Переменные» добавить
**секретную** переменную этапа **«Запуск»** `TEACHER_SETUP_CODE`.
Значение придумать самостоятельно: случайная строка из 24–256 латинских букв,
цифр, дефисов или подчёркиваний (предпочтительно сгенерировать менеджером паролей).
Не использовать пример из документации, не публиковать значение в GitHub или логах.

Обновить приложение до версии с поддержкой этой переменной и перезапустить.
До создания преподавателя сервер заменит прежний автоматически созданный код
на заданный через секрет. На `/teacher/` ввести именно это значение в поле кода,
затем выбрать отдельные логин и пароль преподавателя. После создания учётной
записи переменная больше не действует, в том числе после перезапуска.
Удалить её из панели после успешной настройки. Учётная запись и результаты
останутся на постоянном диске `/data`. Это не способ сбросить существующий пароль.

## Сброс забытого пароля преподавателя в Amvera

Первоначальный `TEACHER_SETUP_CODE` не сбрасывает существующую учётную запись.
Для сброса добавьте другую секретную переменную этапа «Запуск»:
`TEACHER_RESET_CODE`. Задайте новый случайный код из 32 латинских букв и цифр
(допустимы 24–256 букв, цифр, дефисов или подчёркиваний), сохраните его у себя
и перезапустите приложение после обновления до версии с поддержкой сброса.

Откройте `/teacher/#reset-password` (если вы уже вошли — можно нажать «Сбросить пароль» в кабинете). Кнопки «Забыли пароль?» на странице входа нет.
Введите этот код и дважды новый пароль от 12 символов. Логин не меняется.
Существующие входы завершаются, результаты студентов сохраняются. После успеха
удалите `TEACHER_RESET_CODE` из панели хостинга. Код одноразовый: факт использования
сохраняется в базе, и повторное включение той же переменной не позволяет сбросить
пароль ещё раз. Для следующего сброса нужен новый код. Значение никогда не
публикуйте в репозитории, логах или чате. Само добавление переменной не меняет
пароль, пока код не подтверждён через форму.
